### 1.2 背景与问题

LLM 流式输出结构化 JSON 时有三个典型困难：

1. 中途只能拿到前缀，应用想边收边渲染，严格解析器会直接报错。
2. 模型输出常带瑕疵：markdown 代码围栏、单引号、尾逗号、注释、Python 风格字面量，或因 max\_tokens 被截断。
3. 失败时应用需要兜底，而不是整个请求作废。

TypeScript 和 Python 生态已有 jsonrepair、json-repair 等库。MoonBit 生态中我检索到的相关结果里，没有发现同类库，但检索并不完整【待核实：开工前必须在 mooncakes.io 与 GitHub 查重，见 D02】。MoonBit 已有 MCP 服务端 SDK 等 AI 工具链项目，解析 LLM 输出是其自然的配套需求。

## 2. 技术预研报告（D02）

### 2.1 结论摘要

推荐架构：**增量式下推自动机（显式栈）+ 事件接收器（sink）**，同一引擎驱动两种输出：修复文本和 `Json` 值。理由是它天然支持流式、线性复杂度、无递归、状态可枚举，便于属性测试。需要在 Spike 中验证 MoonBit 的 `Json` 类型、字符串处理、错误机制、多后端构建和测试数据装载（D02 第 6 节）。

### 2.2 问题形式化

- 输入：任意字符串 s，可能被截断，可能含瑕疵。
- 一次性修复：`repair(s)` 返回合法 JSON 文本 t（RFC 8259）及修复记录。若 s 本身合法，t 与 s 语义相同。
- 流式：对 s 的前缀序列 p1 ≤ p2 ≤ …，快照 S(p) 满足单调性 S(p1) ⊑ S(p2)，且 S(整串) 与 `repair` 的值一致。
- 偏序 ⊑ 的定义：标量只与自身相等；字符串 a ⊑ b 当且仅当 a 是 b 的前缀；数组 a ⊑ b 当且仅当 a 的元素是 b 的前缀元素，且仅最后一个元素允许是真子关系；对象同理，按键的出现顺序比较，仅最后一个键值允许是真子关系。
- 说明：该定义要求「未结束的数字和字面量」不进入快照（默认策略），否则 12 到 123 会破坏单调性。该策略可配置，见 D05。

### 2.3 现有方案调研

以下来自我已有的知识，本次会话没有逐一核实，列入 Spike S9。

| 方案 | 形态 | 可借鉴点 | 局限 |

| jsonrepair（TypeScript） | 库与 CLI，据我所知含流式变换接口 | 规则覆盖面广，是主要行为对照与测试预言 | 不提供「部分值快照」语义【待核实】 |
| json-repair（Python） | 库 | 第二个 oracle，覆盖 LLM 常见瑕疵 | 偏启发式，行为需逐例核对 |

| MoonBit core 的 `@json.parse` | 标准库 | 严格解析，用作「输出合法性」校验器 | 不容错 |

### 2.4 候选架构对比

| 维度 | A 递归下降加回溯 | B 每次 feed 重解析全缓冲 | C 下推自动机加事件 sink（采纳） | D 正则与分词后处理 |
| --- | --- | --- | --- | --- |
| 流式增量 | 差，需重来 | 可行，总体 O(n²) | 好，总体 O(n) | 差 |
| 深层嵌套 | 递归，有栈溢出风险 | 同 A | 显式栈，无递归 | 不适用 |
| 规则扩展 | 好 | 好 | 中，需维护状态表 | 差 |
| 前瞻与回溯 | 容易 | 容易 | 需显式缓冲，较复杂 | 难 |
| 可测试性 | 中 | 中 | 好，可做分块不变性属性测试 | 差 |
| 结论 | 否决 | 仅作测试中的朴素参照 | **ADR-001 采纳** | 否决 |

### 2.5 关键技术问题与方案

| 编号 | 问题 | 方案 | 残余风险 |
| --- | --- | --- | --- |
| Q1 | 增量与可恢复 | 全部解析状态存入引擎结构，`feed` 只推进状态，不依赖调用栈 | 状态种类多，需状态表与属性测试 |
| Q2 | 字符串内引号歧义，如 `「a 「b」 c」` | 遇到候选结束引号时进入待决状态，向前看第一个非空白字符：属于 `, } ] :` 或输入结束则确认为结束，否则视为内容并转义。作为 P1 选项，默认关闭 | 分块边界上需缓冲；快照里按「已结束」处理 |
| Q3 | 截断的数字与字面量 | 默认不进入快照，`finish` 时按 D05 规则补全或裁剪 | 与其他库的取舍不同，需在差分报告中说明 |
| Q4 | UTF-16 与分块 | 内部以 UTF-16 码元计偏移；高位代理对落在块尾时缓冲到下一块；`feed_bytes` 单独处理 UTF-8 半个字符 | 多后端字符串迭代差异【待核实，Spike S2】 |
| Q5 | 大整数精度 | 修复文本保留数字原文（lexeme），不经过 Double；`Json` 值按 core 约定，文档标明精度损失 | 用户误以为值无损 |
| Q6 | 快照别名与复杂度 | `snapshot()` 返回深拷贝，O(树大小)；`feed` 本身摊还 O(块长)；另提供事件接口避免全量拷贝（P2） | 高频快照时总体 O(n²)，文档提示 |
| Q7 | 去递归 | 显式栈保存容器上下文，深度上限可配置 | 无 |

### 2.7 测试预言与语料方案

- 语料来源：（a）自编规则用例，约 150 条，覆盖每条 BR；（b）从 jsonrepair 与 json-repair 的公开测试中摘录并标注来源，使用前核对许可证；（c）自动变异：对合法 JSON 做截断、删除或插入逗号、引号、括号，生成数千条。
- 预言：对（a）（b）用 jsonrepair 在 Node 上生成期望输出，对比的是解析后的 JSON 值而非文本；（c）以属性为准（输出合法、幂等、分块不变、单调），并抽样与 jsonrepair 对拍。
- 数据流：TS 与 Python 脚本输出 JSON 语料，再由脚本转成 `.mbt` 数据文件（Spike S5），MoonBit 测试读取并比对。

### 2.8 性能预估与基准方法

引擎单趟线性扫描，预期主要开销在字符串拼接与诊断记录。基准输入：1KB、100KB、10MB 三档，覆盖合法 JSON、重度瑕疵 JSON、深层嵌套、超长字符串四类。指标：吞吐（MB/s）、峰值内存、分块大小对吞吐的影响。目标值在 Spike 后确定，见 D04 的 NFR-PERF。

## 4. 软件需求规格说明书（D04）

### 4.1 引言

**目的**：定义 JSONMend 库的功能需求（FR）与非功能需求（NFR），作为设计、测试与验收的依据。

**术语**

| 术语 | 含义 |
| --- | --- |
| 修复（repair） | 把有瑕疵或被截断的输入转换为合法 JSON 文本 |
| 修复记录（Repair） | 一次修改的诊断条目，含修复码、位置、说明 |
| 快照（snapshot） | 流式解析过程中某一时刻对已接收内容的最佳努力值 |
| 分块（chunk） | 流式输入的一次 `feed` 的内容，可在任意位置切分 |
| lexeme | 数字在输入中的原始文本 |
| 预言（oracle） | 测试中用来给出期望结果的参照实现，如 jsonrepair |
| P0 / P1 / P2 | 优先级：必须 / 应该 / 可选，P2 最先被削减 |

### 4.2 总体描述

- 产品形态：MoonBit 库（核心），命令行工具，浏览器演示页（js 后端）。
- 用户：AI 应用开发者、MoonBit 开发者、命令行用户（见 D01 第 1.5 节）。
- 运行环境：MoonBit 工具链，后端 js、wasm-gc、native【待核实：以 Spike S4 为准】。
- 设计约束：核心库不做 IO、不依赖网络、不使用正则、不使用递归。
- 假设：输入为 UTF-16 字符串（`String`）或 UTF-8 字节（`Bytes`），输入视为不可信。

| 接口 | 作用 | 对应 FR |

## 5. 业务规则文档（D05）

### 5.1 总原则

- **P-1 合法性**：成功返回的文本一定是合法 JSON。
- **P-2 最小修改**：多个修复方案可选时，选择改动最小的。
- **P-3 内容保留**：能保留的内容尽量保留，无法保留时才丢弃并记录。
- **P-4 不得无声修改**：每一次改变内容或字面的修改都必须产生修复记录；纯空白规范化除外。
- **P-5 确定性**：同输入同选项必有同输出。

### 5.2 规则总表

| ID | 类别 | 条件与动作 | 修复码 | 优先级 |
| --- | --- | --- | --- | --- |
| BR-01 | 合法性 | 成功返回的文本必须通过 RFC 8259 严格解析，不可关闭 | — | P0 |
| BR-02 | 恒等 | 合法输入的值不变，修复记录为空，文本仅作空白规范化 | — | P0 |
| BR-03 | 幂等 | 对修复文本再次修复，文本相同且无记录 | — | P0 |
| BR-04 | 最小修改 | 见 5.1，冲突时按 5.6 裁决 | — | P0 |
| BR-05 | 围栏与前后缀 | 起始处的围栏行（三个反引号，可带语言标记）跳过，结尾围栏忽略；skip\_prose 开启时丢弃第一个 `{` 或 `[` 之前的文字 | R001 R021 | P0 P1 |
| BR-06 | 引号 | 单引号与弯引号作为界定符，输出统一为双引号，内部的双引号转义；quote\_lookahead 开启时，候选结束引号后的第一个非空白字符不属于逗号、右括号、冒号且输入未结束，则该引号视为内容 | R003 | P0 P1 |

| BR-09 | 逗号与冒号 | 删除尾逗号、前导逗号，折叠连续逗号；相邻两个值之间缺逗号则插入；键后缺冒号则插入 | R005 R006 R007 | P0 |

| BR-14 | 闭合符不匹配 | 栈顶为数组遇到右花括号，当作右方括号；栈顶为对象遇到右方括号，当作右花括号；栈空遇到多余闭合符则忽略 | R015 R017 | P0 |

| BR-16 | 流式快照 | 见 5.4 | — | P0 |
| BR-17 | 严格模式 | Strict 下，任何会产生修复记录的情形改为抛 E010，携带该修复码与位置 | E010 | P0 |
| BR-18 | 资源限制 | 深度、总长、单 token 长超限抛 E020、E021、E022，不返回部分结果 | E02x | P0 |

### 5.4 流式快照语义（BR-16）

| 进行中的元素 | `snapshot()` 默认行为 | `finish()` 行为 |
| --- | --- | --- |
| 字符串值 | 已接收的前缀作为字符串；未完整的转义序列暂不包含 | 补全引号（R010） |
| 字符串键 | 该键不出现 | 键补全并赋 null（R008） |
| 数字 | 不出现（Drop）；TrimToValid 时为最长合法前缀 | 裁剪到合法前缀（R011） |
| 字面量前缀 | 不出现 | 补全（R012） |
| 悬空键（已有冒号无值） | Omit 时不出现；Null 时为 null | 赋 null（R008） |
| 进行中的数组与对象 | 以已确定的内容呈现，状态为 Partial | 补闭合符（R009） |
| 待决引号（前瞻中） | 按已结束处理 | 按 BR-06 判定 |
| 注释中 | 忽略 | 删除（R002） |
| 围栏与前导文字阶段 | 值为空，状态为 Empty | 始终无值则抛 E002 |

**稳定前缀保证**：已闭合的值（完整的字符串、数字、字面量、容器）在之后的快照中不再变化；变化只发生在最后一个未闭合的元素。**单调性**：快照序列满足 D02 2.2 的偏序。选择 TrimToValid 会破坏单调性（12 变为 123），文档中须明示。

`snapshot()` 与 `finish()` 的差异是有意设计：前者是预览，后者是最终修复，悬空键在预览中省略、在最终结果中为 null。

### 5.6 规则优先级与冲突裁决

1. 词法规则（BR-06、08、10、11、12）先于结构规则（BR-09、13、14）。
2. 能同时用「插入」与「删除」修复时，优先保留内容的方案（P-3），其次取改动字符数少者（P-2）。
3. 位于字符串内部的字符一律不触发结构规则。
4. 同一位置命中多条规则时，按本表编号从小到大依次生效，并各记一条记录。

### 7.4 数据流

**一次性修复**

1. M1.1 校验选项，创建引擎与 sink。
2. 整个输入作为一个分块调用引擎，引擎逐码元推进状态机。
3. 引擎每识别出一个值或结构边界，向 sink 发出事件；发现瑕疵时调用 M4 登记修复。
4. 输入结束后调用结束补全（M2.7）。
5. M1.1 从 sink 取出文本或值，连同修复记录与完整性标志返回。

**流式解析**

1. `PartialParser::new` 创建引擎与 sink，保存全部状态。
2. 每次 `feed` 只推进状态机，不输出；不完整的转义、字面量、数字、代理对、待决引号停留在引擎状态中。
3. `snapshot` 取 ValueSink 当前树的拷贝，并按选项叠加引擎中尚未结束的元素。
4. `finish` 执行结束补全，返回最终结果；之后实例进入 Finished 状态。

### 7.6 关键架构决策（ADR）

| 编号 | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| ADR-001 | 增量式下推自动机加事件 sink | 见 D02 2.4 | 状态表需要维护 |
| ADR-002 | 修复在识别器中发现，序列化器按结构写规范 JSON | 逗号与冒号由结构决定，天然消除缺失与多余逗号等问题；登记点集中 | 识别器要显式识别每种瑕疵 |
| ADR-003 | 位置单位为 UTF-16 码元 | 与 MoonBit `String` 一致，避免多后端差异 | 对非 BMP 字符，列号按两个单位计 |
| ADR-004 | 数字规范化只改语法，不改有效数字 | 避免大整数精度损失 | 文本与 `Json` 值可能存在精度差异，文档标明 |
| ADR-005 | 快照为深拷贝 | 避免别名导致调用方看到后续变化 | 高频快照总体 O(n²)，FR-16 作为缓解 |
| ADR-006 | 致命错误（E 码）与修复记录（R 码）分离 | 语义不同：前者中止，后者是信息 | 需要两套类型 |
| ADR-007 | 引号前瞻默认关闭 | 控制 P0 的复杂度 | 默认不处理字符串内的未转义引号 |
| ADR-008 | 显式栈，无递归 | 避免栈溢出，行为一致 | 状态转移代码较长 |
| ADR-009 | 解析器实例非线程安全，不使用全局状态 | 简单、确定 | 并发场景需各自创建实例 |
| ADR-010 | 语料转换为 `.mbt` 数据文件 | 所有后端的测试都能读取 | 数据文件由脚本生成，须提交生成脚本 |

## 8. 详细设计说明书（D08）

### 8.1 约定

- 本节的结构定义与伪代码是设计意图，语法以 Spike 后的真实代码为准。
- 输入以 UTF-16 码元处理。字符类：WS（空格、制表、回车、换行、BOM）、QUOTE（`"` `'` 以及弯引号）、IDENT（字母、下划线、美元符、数字、加减号、点，用于裸词与数字）、LBRACE、LBRACKET、RBRACE、RBRACKET、COMMA、COLON、SLASH、OTHER。
- **设计补充 BR-07a（P1）**：容器内部位置的未识别裸词，作为值时按字符串处理并记 R004；在根位置则不处理，按 E002 报错。实现时同步回写 D05。

### 8.2 核心数据结构

```moonbit
priv enum Phase { Prelude; Body; Epilogue; Finished; Failed }

priv enum Ctx {
  ObjKeyOrEnd    // 刚进入对象或逗号之后，期待键
  ObjColon       // 键之后，期待冒号
  ObjValue       // 冒号之后，期待值
  ObjCommaOrEnd  // 值之后，期待逗号或右花括号
  ArrValueOrEnd  // 刚进入数组或逗号之后，期待值
  ArrCommaOrEnd  // 值之后，期待逗号或右方括号
}

priv enum Tok {
  Idle
  Str(StrState)    // 开引号类型、是否为键、转义子状态
  StrPending       // 候选结束引号，等待前瞻（仅 quote_lookahead 开启）
  Bare             // 裸词：数字、字面量、标识符，终结时分类
  Slash            // 已读到斜杠，尚不知是否注释
  LineComment
  BlockComment(Bool)  // 是否刚读到星号
  Fence(Int)       // 已读到的反引号个数
}
```

| 引擎字段 | 类型 | 作用 |
| --- | --- | --- |
| phase | Phase | 生命周期 |
| stack | Array\[Ctx\] | 容器栈，长度即深度 |
| tok | Tok | 当前未完成的 token |
| buf | StringBuilder | 字符串内容或裸词文本 |
| tok\_start | Position | token 起点，用作修复记录位置 |
| after\_comma | Bool | 当前容器内是否刚读过逗号 |
| last\_comma | Position | 最近一个逗号的位置，供尾逗号记录使用 |
| pending\_ws | StringBuilder | 前瞻期间暂存的空白 |
| root\_done | Bool | 根值是否已完成 |
| pos | Position | 当前位置 |
| opts、sink、repairs | — | 选项、输出层、修复记录 |

### 8.3 主循环

```text
feed(chunk):
  若 phase 为 Finished 或 Failed：抛 E030
  若累计长度超过 max_input_len：抛 E021
  对 chunk 中每个码元 u：
    step(u)

step(u):
  pos 前进（遇换行则行加一、列归一）
  循环：
    按 tok 分派到 Idle 的结构状态转移、字符串、裸词、注释各自的处理函数
    若处理函数返回「重放」（token 被 u 终结，u 需交给结构状态再处理）：
      继续循环，最多重放一次
    否则结束
```

重放机制保证数字、裸词、前瞻这类需要看到下一个字符才能结束的 token，不需要回退输入，也就不依赖整段缓冲，保证了流式。

### 8.4 前导与围栏（M2.1）

- Prelude 阶段跳过空白与 BOM（视为空白，不记录）。
- 行首连续三个反引号且 strip\_fence 开启：吞掉该行剩余内容（语言标记），记 R001，进入 Body。
- skip\_prose 开启：丢弃第一个 `{` 或 `[` 之前的全部内容，整段记一条 R021。
- skip\_prose 关闭时，第一个非空白字符直接按值起点处理。
- Epilogue 阶段遇到围栏行同样吞掉并记 R001。

### 8.5 结构状态转移（M2.6）

「值完成」指一个值（标量或容器）结束：对象内转为 ObjCommaOrEnd，数组内转为 ArrCommaOrEnd，根位置则 root\_done 置真并进入 Epilogue。「容器结束」弹栈后，对父级执行「值完成」。「开始容器」压栈并检查深度，超限抛 E020。

| 状态 | 输入类 | 动作 | 记录 |
| --- | --- | --- | --- |
| ObjKeyOrEnd | QUOTE | 开始键字符串 | — |
| ObjKeyOrEnd | IDENT | 开始裸词（键） | R004 |
| ObjKeyOrEnd | RBRACE | 结束对象；若 after\_comma 则为尾逗号 | R005（位置取 last\_comma） |
| ObjKeyOrEnd | RBRACKET | 当作右花括号 | R015 |
| ObjKeyOrEnd | COMMA | 忽略 | R005 |
| ObjKeyOrEnd | 其他 | 丢弃该字符 | R016 |
| ObjColon | COLON | 转入 ObjValue | — |
| ObjColon | QUOTE 或 IDENT 或 LBRACE 或 LBRACKET | 缺冒号，补上并重放 | R007 |
| ObjColon | RBRACE 或 COMMA | 键无值，补 null，再按输入继续 | R008 |
| ObjValue | QUOTE | 开始值字符串 | — |
| ObjValue | IDENT | 开始裸词（值） | — |
| ObjValue | LBRACE 或 LBRACKET | 开始容器 | — |
| ObjValue | RBRACE 或 COMMA | 缺值，补 null，再按输入继续 | R008 |
| ObjValue | COLON | 忽略 | R016 |
| ObjCommaOrEnd | COMMA | 转入 ObjKeyOrEnd，after\_comma 置真 | — |
| ObjCommaOrEnd | RBRACE | 结束对象 | — |
| ObjCommaOrEnd | RBRACKET | 当作右花括号 | R015 |
| ObjCommaOrEnd | QUOTE 或 IDENT | 缺逗号，补上并重放 | R006 |
| ArrValueOrEnd | 值起点 | 开始对应值 | — |
| ArrValueOrEnd | COMMA | 忽略 | R005 |
| ArrValueOrEnd | RBRACKET | 结束数组；若 after\_comma 则为尾逗号 | R005 |
| ArrValueOrEnd | RBRACE | 当作右方括号 | R015 |
| ArrCommaOrEnd | COMMA | 转入 ArrValueOrEnd，after\_comma 置真 | — |
| ArrCommaOrEnd | RBRACKET | 结束数组 | — |
| ArrCommaOrEnd | RBRACE | 当作右方括号 | R015 |
| ArrCommaOrEnd | 值起点 | 缺逗号，补上并重放 | R006 |
| 任意 | SLASH | 进入 Slash 状态 | — |
| Epilogue | 右括号 | 忽略 | R017 |
| Epilogue | 其他非空白 | 按 multi\_root 处理（见下） | R016 |

**multi\_root**：First 为丢弃剩余内容并只记一条 R016；Error 为抛 E010；Array 为在 Prelude 就隐式压入一个根数组，所有根值作为其元素，值之间用空白或换行分隔时不记 R006，输出始终为数组。

### 8.6 字符串扫描（M2.2）

- 开引号决定可接受的结束引号：`"` 与 `'` 自身；左弯引号接受对应的右弯引号或直引号。开引号为非 `"` 时，开始时记 R003。
- 转义子状态：无、反斜杠之后、`\u` 的第 k 位。

| 转义输入 | 处理 | 记录 |
| --- | --- | --- |
| `\"` `\\` `\/` `\b` `\f` `\n` `\r` `\t` | 解码后存入 buf | — |
| `\u` 加四位十六进制 | 解码为码元存入 buf | — |
| `\u` 后遇到非十六进制 | 丢弃已读部分，该字符作为普通内容重放 | R014 |
| `\'` 或 `\` 加其他字符 | 去掉反斜杠，保留字符 | R014 |
| 输入结束时停在反斜杠或不完整 `\u` | 丢弃 | R014 |
| 未转义控制字符（小于 0x20） | 存入 buf，输出时转义 | R013 |
| 孤立代理码元 | 替换为 U+FFFD | R014 |

- buf 长度超过 max\_token\_len 抛 E022。
- buf 保存的是解码后的内容，TextSink 在输出时负责转义，所以内部引号的转义不需要额外记录。

**引号前瞻（M2.8）**：仅在 quote\_lookahead 开启时启用。遇到候选结束引号，进入 StrPending，后续空白存入 pending\_ws；遇到第一个非空白字符 c：

1. c 属于 `, } ] : /` 之一：确认字符串结束，丢弃 pending\_ws，重放 c。
2. 否则：该引号是内容。把引号与 pending\_ws 追加到 buf，记 R003，字符串继续，c 按内容处理。
3. 输入结束：按确认结束处理。

快照期间的 StrPending 按「已结束」处理。已知局限：`["a" "b"]` 这类缺逗号的情形会被解释为内容，用户在 README 中会看到这一取舍。

### 8.7 裸词与数字（M2.3 与 M2.4 共用）

裸词扫描收集字符，直到遇到分隔符（空白、逗号、冒号、括号、引号、斜杠或输入结束），然后分类：

| 终结时的文本 | 结果 | 记录 |
| --- | --- | --- |
| true、false、null（小写） | 对应字面量 | — |
| True、False、None、TRUE、NULL 等大小写变体 | 对应字面量 | R012 |
| undefined | null | R012 |
| NaN、Infinity、-Infinity | 按 non\_finite：Null、String，或抛 E010 | R012 |
| 完整的合法数字 | 规范化后的数字 | — |
| 数字前缀不完整或带非标准写法（`+1` `.5` `5.` `007` `1e` `-`） | 规范化或裁剪到最长合法前缀 | R011 |
| 输入结束时的字面量前缀（`tru` `nul`） | 补全为唯一匹配的字面量 | R012 |
| 其他，键位置 | 加引号作为键 | R004 |
| 其他，值位置（容器内） | 按 BR-07a 作为字符串 | R004 |
| 其他，根位置 | 失败，E002 | — |

数字规范化规则：去掉前导加号；整数部分去前导零（保留一个 0）；以点开头时补 0；去掉没有小数位的点；指数部分保持原样。规范化只改语法，不改变有效数字（ADR-004）。数字没有任何合法前缀时：对象值位置补 null（R008），数组位置丢弃（R011）。

### 8.8 注释（M2.5）

斜杠之后紧跟斜杠进入行注释，直到换行；紧跟星号进入块注释，直到星号加斜杠；紧跟其他字符则丢弃斜杠（R016）并重放该字符。每个注释在起点记一条 R002。输入结束时仍在注释中，视为注释结束。Slash 与 BlockComment 的中间状态保存在引擎里，所以在斜杠与星号之间被分块切开也能正确处理。

### 8.9 ValueSink 与快照（M3.3）

- 存储：`root : Json?`，以及帧栈。数组帧保存元素数组；对象帧保存有序的键值条目数组加键索引表（不依赖 core 的 Map 保序，见 OPEN-1），以及起始时记录的「挂到父级的键」。
- 容器结束时，把该帧物化为 `Json` 并挂到父级；根容器结束则成为 root。
- 重复键策略：Last 保留首次出现的位置并替换值，记 R018；First 忽略后者，记 R018；Error 抛 E010。

**快照算法**

1. 自栈底到栈顶，把每个开放帧当前的条目拷贝为部分容器，已闭合子树用显式栈做深拷贝（不递归）。
2. 叠加引擎当前未结束的元素，规则见 D05 5.4：开放的字符串值追加到栈顶帧；开放的键不出现；数字与字面量按 incomplete\_number；悬空键按 pending\_key。
3. 自栈顶向栈底，把每个部分容器挂到其父容器的对应槽位。
4. 返回结果：栈空且根已完成则为完整值；尚无任何值则 value 为空且状态为 Empty；其他为 Partial。
5. `open_path`：每个开放帧贡献一段，对象帧取其当前键，数组帧取当前元素下标。

复杂度为 O(树大小)。后续优化可对已闭合子树做结构共享，但会引入别名问题，v0.1 不做。

### 8.10 TextSink（M3.2）

- 每层维护 need\_comma 标志；写值之前按需写逗号，键之后写冒号，因此源输入里的逗号与冒号问题在输出端自然消失（ADR-002）。
- 字符串转义：`"` 与反斜杠加反斜杠；退格、换页、换行、回车、制表用短转义；其他小于 0x20 的控制字符用 `\u00xx`（小写十六进制）；其他字符原样输出。
- 数字写入规范化后的文本。indent 为零时紧凑输出；大于零时换行加缩进。
- 出现致命错误时，已写入的内容全部丢弃。

### 8.11 结束补全（M2.7）

```text
finish():
  若 phase 为 Finished：抛 E030
  若 tok 为 StrPending：按确认结束处理
  按 tok 终结当前 token：
    Str       补全引号（R010）；若为键则进入「悬空键」处理
    Bare      以输入结束为条件分类（字面量前缀补全，数字裁剪）
    Slash     丢弃（R016）
    注释与围栏  直接结束
  自栈顶向栈底展开：
    ObjColon 或 ObjValue：为悬空键补 null（R008）
    其他状态：after_comma 为真则记尾逗号（R005）
    发出该容器的结束事件，记 R009
  若从未产生根值：只有空白或为空则 E001，否则 E002
  phase 置为 Finished，返回结果
```

### 8.12 诊断登记入口（M4.4）

```text
report(code, pos, msg):
  若 mode 为 Strict，或 code 被 rules 关闭：抛 E010（携带 code、pos、msg）
  若 collect_repairs 且记录数未达内部上限 10000：追加一条记录
```

达到内部上限后不再追加记录，Strict 的升级不受影响。该容量限制将写入 D09 与 README。

### 8.13 位置跟踪（M4.1）

offset 每个码元加一；遇到换行则 line 加一、column 置 1，其他码元 column 加一；回车只增加 column，因此 CRLF 只算一次换行。修复记录的位置取该构造的第一个字符，即 tok\_start 或当时的 pos。流式输入的位置累计，不随分块重置。

### 8.14 UTF-8 增量解码（M6.3）

解码器保存「还需几个后续字节」「已累积的码点」「该长度允许的最小码点」。遇到非法首字节、后续字节错误、过长编码、代理区码点或大于 U+10FFFF，抛 E040，携带字节偏移；`finish` 时仍有未完成序列也抛 E040。解码出的码点拆成 UTF-16 码元后交给 `feed` 的同一条路径。输入开头的 EF BB BF 视为 BOM，静默跳过。

### 8.15 复杂度与内存

- 时间：每个码元最多被处理一次，加至多一次重放，前瞻缓冲摊还，总体 O(n)。
- 空间：O(深度) 的栈、O(最大 token 长度) 的缓冲，加上 sink 的输出和修复记录。
- 快照：O(树大小)，由调用方控制频率。

| `{` | `{}`，R009 |
| `[` | `[]`，R009 |
| `"` | 空字符串 `""`，R010 |
| `"abc` | `"abc"`，R010 |
| `}` | E002（R017 被记录后无根值） |

## 9. 错误体系专项设计（D09）

### 9.1 目标与原则

1. 两类信号严格分开：\*\*致命错误（E 码）\*\*中止处理并抛出；\*\*修复记录（R 码）\*\*是信息，随结果返回。
2. 库内任何路径都不使用会中止进程的操作。对任意输入，只可能返回结果或抛出 `MendError`。
3. 码一经发布含义不变；0.x 阶段只新增、不改动、不复用已有码。
4. 错误信息使用简短英文，机器可读字段齐全；文档使用中文说明。
5. 失败时不返回部分结果；抛出错误时，已生成的文本全部丢弃。

### 9.2 类型设计（草案，以 Spike S3 为准）

```moonbit
pub(all) enum RepairCode {
  StripFence; StripComment; NormalizeQuote; QuoteBareWord
  RemoveExtraComma; InsertComma; InsertColon; FillNull
  CloseContainer; CloseString; FixNumber; ConvertLiteral
  EscapeControl; FixEscape; MismatchedCloser; DropUnexpected
  DropExtraCloser; MergeDuplicateKey; ConcatStrings
  DropEllipsis; SkipProse
}

pub suberror MendError {
  EmptyInput
  NoJsonFound(Position)
  StrictViolation(RepairCode, Position, String)
  DepthLimit(Int, Position)
  SizeLimit(Int, Int)
  TokenLimit(Int, Position)
  InvalidState(String)
  InvalidUtf8(Int)
  InvalidOption(String)
}
```

两个类型各提供 `code()` 方法，返回稳定字符串（如 R005、E010），并实现 `Show`。若 Spike S3 表明 `raise` 不便使用，则改为所有入口返回 `Result[T, MendError]`，错误码与载荷不变。

### 9.3 致命错误码（E）

| 码 | 名称 | 触发条件 | 携带数据 | 抛出位置 | 建议处理 |
| --- | --- | --- | --- | --- | --- |
| E001 | EmptyInput | 输入为空或只有空白 | 无 | `repair` `parse` `finish` | 视为「无内容」，由调用方决定默认值 |
| E002 | NoJsonFound | 有内容，但没有任何可识别的 JSON 值 | 位置 | 同上 | 提示用户检查输入，或开启 skip\_prose |
| E010 | StrictViolation | Strict 模式下遇到本需修复的情形；规则被关闭；duplicate\_keys、non\_finite、multi\_root 取 Error | 触发的 R 码、位置、说明 | `feed` `finish` `repair` `parse` | 改用 Lenient，或修正上游输出 |
| E020 | DepthLimit | 嵌套深度超过 max\_depth | 上限、位置 | `feed` | 判定为恶意或异常输入 |
| E021 | SizeLimit | 累计输入超过 max\_input\_len | 上限、实际值 | `feed` `repair` | 分段处理或调大上限 |
| E022 | TokenLimit | 单个字符串或裸词超过 max\_token\_len | 上限、位置 | `feed` | 同上 |
| E030 | InvalidState | 在 Finished 或 Failed 状态下继续调用，或内部不可达分支 | 说明 | `feed` `finish` | 每个输入流使用新的解析器实例 |
| E040 | InvalidUtf8 | 字节输入不是合法 UTF-8，或结束时有未完成序列 | 字节偏移 | `feed_bytes` `finish` | 检查上游编码 |
| E050 | InvalidOption | 选项值非法，如 max\_depth 小于等于零 | 说明 | `new` `repair` `parse` | 修正参数 |

### 9.5 严格模式与升级规则

- 所有登记都经过统一入口（D08 8.12）。Strict 模式下，第一次登记就抛 E010，载荷含触发的 R 码、位置与说明。
- `rules` 开关关闭某个 R 码，等价于对该码单独启用 Strict。
- duplicate\_keys 取 Error、non\_finite 取 Error、multi\_root 取 Error，也抛 E010，载荷里的 R 码分别为 R018、R012、R016。
- 合法 JSON 输入在任何模式下都不会触发 E010。

### 9.6 各 API 的错误行为

| API | 可能抛出 | 失败后的状态 |
| --- | --- | --- |
| `repair` `parse` | E001 E002 E010 E020 E021 E022 E050 | 无状态，无残留 |
| `PartialParser::new` | E050 | 不创建实例 |
| `feed` | E010 E020 E021 E022 E030 | 进入 Failed；之后的 `feed` 与 `finish` 抛 E030 |
| `feed_bytes` | 同 `feed`，另加 E040 | 同上 |
| `snapshot` | 不抛出 | Failed 状态下尽力返回失败时已构建的内容，不保证单调 |
| `finish` | E001 E002 E010 E030 | 进入 Finished 或 Failed |

若 Spike S3 允许，另提供不抛出的变体 `try_repair` 与 `try_parse`，返回 `Result`（P1）。

### 9.7 位置、上下文与消息格式

- 位置约定见 BR-20；流式输入的位置累计。
- 一次性入口可以附带上下文片段：取出错位置所在行，截取前后各约 20 个码元，并在下一行用插入符标出列。流式解析器不保存输入，所以不提供片段。
- `Show` 的格式：`E010 StrictViolation at 3:14 (offset 27): R005 RemoveExtraComma: trailing comma removed`。
- 修复记录的 `message` 使用固定模板，不含用户输入内容，避免日志注入。

### 9.8 命令行退出码与输出

| 退出码 | 含义 | 对应错误 |
| --- | --- | --- |
| 0 | 成功（可能有修复） | — |
| 1 | `--check` 模式下发现需要修复的内容 | — |
| 2 | 命令行用法错误 | E050 |
| 3 | 输入无效 | E001 E002 E040 |
| 4 | 资源限制 | E020 E021 E022 |
| 5 | 严格模式违规 | E010 |
| 70 | 内部错误 | E030（内部不可达） |

修复后的文本写 stdout；`--report` 时把修复记录逐行写 stderr，格式为 `R005 3:14 trailing comma removed`；错误信息写 stderr。

### 9.9 失效模式

| 失效模式 | 检测 | 响应 | 用户可见结果 |
| --- | --- | --- | --- |
| 输入过大 | 累计长度检查 | E021 | 无部分结果 |
| 嵌套过深 | 压栈时检查 | E020 | 同上 |
| 单 token 过长 | 缓冲长度检查 | E022 | 同上 |
| 非法 UTF-8 | 解码器 | E040 | 同上 |
| 调用顺序错误 | 生命周期状态 | E030 | 同上 |
| 内部不变量被破坏（缺陷） | 不可达分支 | E030，说明中标注 internal | 视为缺陷，由模糊测试捕获 |
| 修复记录过多 | 内部上限 10000 | 停止追加记录，Strict 升级不受影响 | README 中说明 |

### 9.10 测试要求（对应 TC-E）

- 每个 E 码至少一个触发用例，并断言载荷与位置。
- 每个 R 码至少一个用例，断言位置与严重度；再由同一份用例表自动派生一个 Strict 用例，断言升级为 E010 且载荷里的 R 码相同。
- 同一输入按不同方式分块，得到的修复记录（含位置）必须逐条相同。
- Failed 与 Finished 之后的调用行为用例。
- 内部不可达分支不得被任何测试或模糊用例触发。

### 9.11 演进与兼容

新增码只追加编号；废弃码保留编号并在文档标注；公共类型的变体新增视为兼容变更，在 CHANGELOG 中说明。

### 11.5 属性与模糊测试（TC-P）

| 编号 | 属性 | 生成器 | 规模 |
| --- | --- | --- | --- |
| TC-P-01 | 若返回成功，输出文本能被 core 严格解析 | G1 对合法 JSON 做变异；G2 随机拼接 JSON 字母表中的 token；G3 随机 UTF-16 序列含孤立代理项 | 不少于 20 万例 |

### 11.8 差分测试（TC-D）

**流程**

1. 收集输入：（a）自编黄金用例的输入；（b）从参照库公开测试中摘录并标注来源与许可证（核对通过才可使用，RSK-09）；（c）自动变异语料，数千条。
2. 在 Node 上用 jsonrepair、在 Python 上用 json-repair 生成期望，记录输出或异常。
3. 脚本把输入与期望转成 `.mbt` 数据文件并提交，同时记录参照库与运行时版本。
4. MoonBit 测试逐条运行并比对**解析后的 JSON 值**是否相等，而不是比较文本。
5. 对不相等的用例分类并记入 `docs/DIVERGENCES.md`。

**分类**

| 类别 | 含义 | 处理 |
| --- | --- | --- |
| Equal | 值相等 | 计入等价 |
| DiffIntentional | 设计上有意不同（如快照策略、孤立代理项） | 写明理由与对应的 BR |
| DiffBug | 本库缺陷 | 修复并加回归用例 |
| OutOfScope | 参照库做了范围外的猜测式修复 | 说明并排除 |
| RefError | 参照库自身报错或不稳定 | 排除并说明 |

**指标**：等价率 = Equal 除以（总数减 OutOfScope 减 RefError）。目标：整体不低于 90%，P0 规则用例中除 DiffIntentional 外 100% 等价。参照库的版本变化可能影响结果，因此语料与期望随版本冻结后提交。

分歧记录模板：编号、输入（过长则截断）、本库输出、参照输出、类别、理由、关联规则。参照库只用于行为对照，不复制其源码。

### 12.10 一页项目说明草稿（可直接用于申报，按需修改）

**项目名称**：JSONMend——流式 JSON 修复与部分解析库

**要解决的问题**：LLM 输出的结构化 JSON 经常被截断或带有瑕疵，流式场景下应用只能拿到前缀。TypeScript 与 Python 有成熟方案，MoonBit 生态中尚缺对应能力（以开工前的查重结论为准）。

**方案**：用增量式下推自动机加事件 sink 的单一引擎，同时提供一次性修复与流式部分解析；每次修改都有带位置的修复记录；支持严格模式与资源限制。

**与 MoonBit 的契合**：枚举与模式匹配适合写状态机；多后端与小体积适合在浏览器、服务端与命令行复用；与已有的 MCP 等 AI 工具链项目互补。

**可验证性**：属性测试（分块不变、快照单调、输出合法）、与 jsonrepair 的差分报告、多后端一致性。

**里程碑**：10-16 技术验证；10-21 一次性修复完成；10-25 流式完成；10-28 功能冻结；10-30 提交验收。

**风险与应对**：工期短，按优先级分层并预先约定削减顺序；选题重复，以差分报告与流式快照语义作差异化。

### 12.11 已知限制（对外披露）

- `snapshot()` 返回完整拷贝，代价与树大小成正比，高频调用时总体开销较大；FR-16 的事件接口可缓解。
- `Json` 数值遵循 core 的表示，大整数可能损失精度；修复后的文本保留数字原文。
- 引号前瞻默认关闭，开启后对缺逗号的字符串序列会偏向解释为内容。
- 修复记录有内部上限 10000 条。
- 解析器实例非线程安全，每个输入流应使用独立实例。
- 与 jsonrepair 存在有意差异，详见差分报告。
- 后端支持范围以发布时的测试结果为准。

### A.5 推导过程中发现的设计问题（需回写）

1. **D05 BR-02 与 BR-03 的措辞过强**。G-084、G-085 表明合法输入里的 `\u00e9`、`\/` 会被输出端按规范写法重新编码，文本变了、值没变。应把「恒等」改成「值恒等；文本在空白与转义写法上可被规范化」，并在 README 中说明。
2. **D08 8.13 的位置约定需要补一句**：改写与删除类取首字符，插入类取插入点（G-052、G-054、G-090 至 G-102 依赖这一约定）。
3. **一个输入可产生多条同位置记录**。G-090 有两条 R009 同在偏移 9，G-095 同一偏移上有 R010、R008、R009 三条。这符合「一次修改一条记录」，但对用户有噪声。若希望合并，需要改 BR-19，并同步修改 D09。
4. **G-077 只记 R008，不记 R011**。这是 D08 8.7 的字面结果：没有任何合法前缀的数字被替换为 null。若希望也记录被丢弃的残留，需要改规则。
5. **覆盖缺口**：本批没有覆盖 BR-18 的资源限制、孤立代理项（BR-12）、BR-21、选项矩阵（TC-O）和 R004 值位置的 BR-07a；下一批补齐。

### B.4 推导过程中发现的设计问题（需回写）

1. **E021 必须按码元检测，且载荷与分块无关。** D08 8.3 写的是在 `feed` 开头按累计长度检测，这会让错误载荷随分块而变，违反 NFR-COR-03。应改为：处理到第 `max_input_len + 1` 个码元时抛错，载荷为超限的首个码元偏移（G-203）。同时约定 E022 的位置取 token 起点（G-205）。
2. **D08 8.5 的转移表缺少「无法归类字符」的行。** 在 ObjColon、ObjValue、ObjCommaOrEnd、ArrValueOrEnd、ArrCommaOrEnd 状态遇到 OTHER 类字符，应丢弃并记 R016（G-230、G-232）；在根位置尚无值时遇到 OTHER，应直接抛 E002（G-250）。
3. **IDENT 字符类是否包含非 ASCII 字母需要决定。** 这决定 `{"a":你好}` 是被当作裸词字符串，还是被丢弃。建议按「非 ASCII 且不是空白或标点」近似处理，并在 Spike S2 中确认 MoonBit 提供字符分类的方式。
4. **skip\_prose 会吞掉开头的围栏。** 此时只记 R021，不再有开头的 R001，只有结尾围栏记 R001（G-291）。D05 BR-05 需写明。
5. **省略号与字符串拼接要按「值」处理。** 把 `...` 视为一个被丢弃的值，相邻逗号才会自然合并（G-301 至 G-303）；`+` 拼接则要在逗号或结束状态里特判（G-300）。D08 未设计这两处，属于 P2，实现时补。
6. **转义形式的孤立代理项也要处理。** G-224 表明 `\uD83D` 后不跟低位时同样替换为 U+FFFD，记录位置取反斜杠。D05 BR-12 目前只写了原文里的孤立码元，需要补上。
