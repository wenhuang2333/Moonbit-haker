# 7. 概要设计说明书（D07）

## 7.1 设计目标与驱动因素

| 驱动因素 | 来源 | 设计响应 |
| --- | --- | --- |
| 流式与一次性行为一致 | G2 NFR-COR-03 | 单一引擎，两种入口 |
| 线性时间、无栈溢出 | NFR-PERF-01 NFR-ROB-02 | 显式栈、单趟扫描、无递归 |
| 每次修改可审计 | BR-19 | 修复在识别器中发现并登记，序列化器只写规范 JSON |
| 多后端一致 | G4 | 不依赖平台特有 API，字符串按 UTF-16 码元处理 |
| 体积与对外面小 | NFR-SIZE-01 NFR-API-01 | 内部包不对外，公共符号控制在约 15 个以内 |

## 7.2 架构总览

分层如下，上层依赖下层，下层不依赖上层。

| 层 | 内容 | 说明 |
| --- | --- | --- |
| 接入层 | M1 门面：`repair`、`parse`、`PartialParser`、结果类型 | 唯一对外 API |
| 引擎层 | M2 识别器：把字符流转换为规范化事件流，并在发现瑕疵时登记修复 | 只产生事件，不知道输出长什么样 |
| 输出层 | M3 sink：TextSink 写修复文本；ValueSink 构建 `Json` 并生成快照；TeeSink 同时驱动两者 | 通过 Sink 接口解耦 |
| 支撑层 | M4 诊断与错误；M5 选项；M6 文本工具（字符分类、代理对、UTF-8 解码） | 被各层使用 |
| 应用层 | M7 命令行；M8 演示页 | 只依赖 M1 |
| 测试层 | M9 测试套件、语料装载、生成器、切分器 | 只依赖 M1 |

## 7.4 数据流

**一次性修复**

1. M1.1 校验选项，创建引擎与 sink。
2. 整个输入作为一个分块调用引擎，引擎逐码元推进状态机。
3. 引擎每识别出一个值或结构边界，向 sink 发出事件；发现瑕疵时调用 M4 登记修复。
4. 输入结束后调用结束补全（M2.7）。
5. M1.1 从 sink 取出文本或值，连同修复记录与完整性标志返回。

**流式解析**

1. `PartialParser::new` 创建引擎与 sink，保存全部状态。
2. 每次 `feed` 只推进状态机，不输出；不完整的转义、字面量、数字、代理对、待决引号停留在引擎状态中。
3. `snapshot` 取 ValueSink 当前树的拷贝，并按选项叠加引擎中尚未结束的元素。
4. `finish` 执行结束补全，返回最终结果；之后实例进入 Finished 状态。

## 7.5 对外类型与接口草案

以下为接口草案，语法与签名以 Spike S3 通过编译的结果为准。

```moonbit
pub(all) struct Position {
  offset : Int
  line : Int
  column : Int
}

pub(all) enum Severity { Info; Warning }

pub(all) struct Repair {
  code : RepairCode
  position : Position
  severity : Severity
  message : String
}

pub(all) enum Completeness { Empty; Partial; Complete }

pub(all) enum PathSegment { Key(String); Index(Int) }

pub(all) struct RepairResult {
  text : String
  repairs : Array[Repair]
  completeness : Completeness
}

pub(all) struct ParseResult {
  value : Json
  repairs : Array[Repair]
  completeness : Completeness
}

pub(all) struct Snapshot {
  value : Json?
  completeness : Completeness
  open_path : Array[PathSegment]
}

pub fn repair(input : String, options? : Options) -> RepairResult raise MendError
pub fn parse(input : String, options? : Options) -> ParseResult raise MendError

pub fn PartialParser::new(options? : Options) -> PartialParser raise MendError
pub fn PartialParser::feed(self : PartialParser, chunk : String) -> Unit raise MendError
pub fn PartialParser::feed_bytes(self : PartialParser, bytes : Bytes) -> Unit raise MendError
pub fn PartialParser::snapshot(self : PartialParser) -> Snapshot
pub fn PartialParser::finish(self : PartialParser) -> FinalResult raise MendError
```

`FinalResult` 同时包含 `text`、`value`、`repairs`，是否生成 `text` 由 `want_text` 控制。

## 7.6 关键架构决策（ADR）

| 编号 | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| ADR-001 | 增量式下推自动机加事件 sink | 见 D02 2.4 | 状态表需要维护 |
| ADR-002 | 修复在识别器中发现，序列化器按结构写规范 JSON | 逗号与冒号由结构决定，天然消除缺失与多余逗号等问题；登记点集中 | 识别器要显式识别每种瑕疵 |
| ADR-003 | 位置单位为 UTF-16 码元 | 与 MoonBit `String` 一致，避免多后端差异 | 对非 BMP 字符，列号按两个单位计 |
| ADR-004 | 数字规范化只改语法，不改有效数字 | 避免大整数精度损失 | 文本与 `Json` 值可能存在精度差异，文档标明 |
| ADR-005 | 快照为深拷贝 | 避免别名导致调用方看到后续变化 | 高频快照总体 O(n²)，FR-16 作为缓解 |
| ADR-006 | 致命错误（E 码）与修复记录（R 码）分离 | 语义不同：前者中止，后者是信息 | 需要两套类型 |
| ADR-007 | 引号前瞻默认关闭 | 控制 P0 的复杂度 | 默认不处理字符串内的未转义引号 |
| ADR-008 | 显式栈，无递归 | 避免栈溢出，行为一致 | 状态转移代码较长 |
| ADR-009 | 解析器实例非线程安全，不使用全局状态 | 简单、确定 | 并发场景需各自创建实例 |
| ADR-010 | 语料转换为 `.mbt` 数据文件 | 所有后端的测试都能读取 | 数据文件由脚本生成，须提交生成脚本 |

## 7.8 技术选型与构建

- 运行时依赖：仅 MoonBit core（`Json` 等）。
- 开发期工具：Node.js 运行 jsonrepair，Python 运行 json-repair 与语料脚本。
- 构建与测试命令：类型检查、格式化、测试、按后端构建，具体写法以安装版本的帮助输出为准，并固化到 `Makefile` 或脚本，供验收复现。

## 7.9 质量属性实现策略

| 属性 | 策略 |
| --- | --- |
| 线性性能 | 单趟扫描；使用缓冲区拼接；诊断可关闭 |
| 无崩溃 | 不使用会中止的操作；所有索引访问先判界；模糊测试 |
| 分块不变 | 全部状态持久化到引擎；跨块缓冲仅限代理对、转义、前瞻三处，并有专项测试 |
| 可审计 | 所有修改经 M4 登记，无旁路 |
| 体积 | 不引入多余依赖；诊断消息使用静态字符串 |
| 易用 | 默认参数合理，三行完成修复 |
