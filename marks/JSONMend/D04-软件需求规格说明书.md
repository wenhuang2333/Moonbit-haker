# 4. 软件需求规格说明书（D04）

## 4.1 引言

**目的**：定义 JSONMend 库的功能需求（FR）与非功能需求（NFR），作为设计、测试与验收的依据。

**术语**

| 术语 | 含义 |
| --- | --- |
| 修复（repair） | 把有瑕疵或被截断的输入转换为合法 JSON 文本 |
| 修复记录（Repair） | 一次修改的诊断条目，含修复码、位置、说明 |
| 快照（snapshot） | 流式解析过程中某一时刻对已接收内容的最佳努力值 |
| 分块（chunk） | 流式输入的一次 `feed` 的内容，可在任意位置切分 |
| lexeme | 数字在输入中的原始文本 |
| 预言（oracle） | 测试中用来给出期望结果的参照实现，如 jsonrepair |
| P0 / P1 / P2 | 优先级：必须 / 应该 / 可选，P2 最先被削减 |

## 4.2 总体描述

- 产品形态：MoonBit 库（核心），命令行工具，浏览器演示页（js 后端）。
- 用户：AI 应用开发者、MoonBit 开发者、命令行用户（见 D01 第 1.5 节）。
- 运行环境：MoonBit 工具链，后端 js、wasm-gc、native【待核实：以 Spike S4 为准】。
- 设计约束：核心库不做 IO、不依赖网络、不使用正则、不使用递归。
- 假设：输入为 UTF-16 字符串（`String`）或 UTF-8 字节（`Bytes`），输入视为不可信。

## 4.3 外部接口概览（接口草案）

| 接口 | 作用 | 对应 FR |
| --- | --- | --- |
| `repair(input, options) -> RepairResult` | 一次性修复，返回文本、修复记录、完整性 | FR-01 02 04 05 |
| `parse(input, options) -> ParseResult` | 一次性修复并返回 `Json` 值 | FR-03 |
| `PartialParser::new(options)` | 创建流式解析器 | FR-09 |
| `PartialParser::feed(chunk)` / `feed_bytes(bytes)` | 推进解析 | FR-09 11 12 |
| `PartialParser::snapshot() -> Snapshot` | 取当前快照 | FR-10 |
| `PartialParser::finish() -> FinalResult` | 结束输入并取最终结果 | FR-09 |
| `Options` | 选项集合，见 4.6 | FR-13 |
| `MendError` | 致命错误，见 D09 | FR-13 |
| CLI `jsonmend` | 命令行 | FR-17 |

以上签名为草案，最终以编译通过的代码和 D07 为准。

## 4.4 功能需求（FR）

| ID | 名称 | 描述 | 优先级 | 验收准则 |
| --- | --- | --- | --- | --- |
| FR-01 | 一次性修复 | 对任意输入返回合法 JSON 文本、修复记录、完整性标志 | P0 | 输入 `{'a':1,}` 得到 `{"a":1}` |
| FR-02 | 修复报告 | 每次修改产生一条记录，含修复码、位置、说明、严重度 | P0 | 上例含 R003 与 R005，位置正确 |
| FR-03 | 值输出 | `parse` 返回 `Json` 值与修复记录 | P0 | 值与 `repair` 文本经 core 解析器解析的结果相等 |
| FR-04 | 合法输入恒等 | 合法 JSON 输入的值不变，修复记录为空 | P0 | 随机合法 JSON 属性测试通过 |
| FR-05 | 截断补全 | 补全未闭合的字符串、数组、对象、字面量、数字 | P0 | `{"a":[1,2` 得 `{"a":[1,2]}`；`{"a":"he` 得 `{"a":"he"}` |
| FR-06 | 词法宽容 | 处理单引号与弯引号、无引号键、注释、Python 与 JS 字面量、控制字符与非法转义、非标准数字 | P0 | BR-06 至 BR-12 的全部示例通过 |
| FR-07 | 结构修复 | 处理尾逗号、缺逗号、缺冒号、缺值、闭合符不匹配与多余 | P0 | BR-09 BR-13 BR-14 示例通过 |
| FR-08 | 围栏与前后缀 | 去除 markdown 代码围栏（P0）；跳过 JSON 之前的说明文字（P1） | P0/P1 | 以 \`\`\`json 开头的输入被正确提取 |
| FR-09 | 流式解析器 | 提供 new、feed、snapshot、finish 完整生命周期 | P0 | 先 feed `{"a":"he` 得快照 `{"a":"he"}`，再 feed `llo"}` 后 finish 得 `{"a":"hello"}` |
| FR-10 | 快照语义 | 实现 BR-16：稳定前缀、单调性、未完成元素的处理策略 | P0 | 单调性属性测试通过 |
| FR-11 | 分块鲁棒 | 在转义序列、`\u` 序列、字面量、数字、代理对、围栏等位置任意切分，结果与一次性一致 | P0 | 随机切分属性测试不少于 10 万例通过 |
| FR-12 | 字节输入 | `feed_bytes` 正确处理被切开的 UTF-8 多字节字符，非法序列报 E040 | P1 | 把含中文与 emoji 的输入按每字节切分，结果一致 |
| FR-13 | 选项与模式 | 严格与宽松模式、资源限制、重复键策略、未完成数字策略（P0）；规则开关集合（P1） | P0/P1 | 每个选项至少一个用例，默认值与 4.6 一致 |
| FR-14 | 引号歧义前瞻 | 字符串内未转义的引号按后续字符判定（可选，默认关闭） | P1 | BR-06 中的歧义示例通过且分块不变 |
| FR-15 | 多根值 | 支持首个值、数组聚合、报错三种策略（NDJSON 场景） | P1 | 三种策略各有用例 |
| FR-16 | 事件接口 | 暴露解析事件或文本增量，避免全量快照拷贝 | P2 | 事件序列重放得到同一棵树 |
| FR-17 | 命令行 | `jsonmend [--strict] [--indent N] [file]`，标准输入输出，报告写 stderr，退出码见 D09 | P1 | 管道输入输出与退出码用例通过 |
| FR-18 | 浏览器演示 | 文本框模拟流式输入，并展示快照与修复记录 | P1 | 演示页可在本地按 README 复现 |
| FR-19 | 字符串拼接与省略号 | 合并 `"a" + "b"`，删除 `...` 占位 | P2 | BR-21 示例通过 |
| FR-20 | 缩进输出 | 修复文本支持缩进 | P2 | `--indent 2` 输出符合预期 |

## 4.6 数据需求与选项字典

| 选项 | 取值 | 默认 | 说明 | 优先级 |
| --- | --- | --- | --- | --- |
| mode | Lenient / Strict | Lenient | Strict 下任何修复都抛 E010 | P0 |
| max\_depth | 正整数 | 512 | 容器嵌套深度上限 | P0 |
| max\_input\_len | 正整数 | 64 Mi 码元 | 总输入上限 | P0 |
| max\_token\_len | 正整数 | 16 Mi 码元 | 单个字符串或数字上限 | P0 |
| duplicate\_keys | Last / First / Error | Last | 重复键策略 | P0 |
| incomplete\_number | Drop / TrimToValid | Drop | 快照中未结束数字与字面量的处理 | P0 |
| pending\_key | Omit / Null | Omit | 快照中悬空键的处理 | P0 |
| non\_finite | Null / Error / String | Null | NaN 与 Infinity 的处理 | P0 |
| strip\_fence | 布尔 | true | 去除代码围栏 | P0 |
| collect\_repairs | 布尔 | true | 关闭可提高吞吐 | P0 |
| want\_text | 布尔 | true | 流式解析器是否同时生成修复文本 | P0 |
| skip\_prose | 布尔 | false | 跳过 JSON 之前的说明文字 | P1 |
| quote\_lookahead | 布尔 | false | 引号歧义前瞻 | P1 |
| multi\_root | First / Array / Error | First | 多根值策略 | P1 |
| rules | 规则开关集合 | 全开 | 按 R 码关闭单条规则 | P1 |
| indent | 非负整数 | 0 | 输出缩进 | P2 |

输入输出的字符集：输入为任意 UTF-16 码元序列；输出为合法 JSON 文本，非 ASCII 字符原样保留，控制字符一律转义。
