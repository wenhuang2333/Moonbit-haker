# 附录 A 首批测试用例（TC-G 77 条，TC-S 10 组）

## A.1 说明与约定

这批用例由 D08 的状态机手工推导，用来作为开工后第一批可落地的测试。**期望值未经任何实现验证，提交前必须人工评审**；实现与期望不符时，先判断是设计缺口还是用例写错，再决定改哪一边（D11 11.4）。

- 偏移为 UTF-16 码元，从 0 起；记录写作 `R005@6`，表示修复码 R005、偏移 6。错误写作 `E010(R005@6)`。
- 位置约定（见 A.5 的第 2 条发现）：删除或改写类取该构造的第一个字符；插入类（R006、R007、R008、R009、R010）取插入点，在输入结尾时取输入总长度。
- 符号：`⏎` 表示换行（U+000A），`␍` 表示回车（U+000D），`␀` 表示 U+0000。期望文本中的反斜杠转义是字面的两个字符。
- 选项一栏留空表示默认选项。多条记录之间用逗号分隔，顺序即发生顺序。
- 每条用例在测试时还要自动派生两个变体：按每个码元切分的流式运行、按每个二分位置切分的流式运行，两者的文本、值、记录（含偏移）必须与一次性结果完全相同（TC-P-03）；Strict 变体由记录表派生（D09 9.10）。

## A.4 比对逻辑（伪代码）

```text
对每条用例：
  结果 = 一次性运行（输入，选项）
  断言 结果 与 期望 在文本、记录（码与偏移，必要时含行列）上完全一致
  对 输入 的每个切分方式（逐码元；每个二分位置）：
    结果2 = 流式运行（切分后的输入，选项）
    断言 结果2 与 结果 在文本、值、记录、错误上完全一致
  若期望为成功，且选项为默认：
    断言 对结果文本再运行一次，文本不变且无记录（幂等）
    断言 结果文本可被 core 严格解析（合法性）
  若记录表非空：派生 Strict 变体，断言得到 E010，载荷中的修复码等于第一条记录
```

## A.5 推导过程中发现的设计问题（需回写）

1. **D05 BR-02 与 BR-03 的措辞过强**。G-084、G-085 表明合法输入里的 `\u00e9`、`\/` 会被输出端按规范写法重新编码，文本变了、值没变。应把「恒等」改成「值恒等；文本在空白与转义写法上可被规范化」，并在 README 中说明。
2. **D08 8.13 的位置约定需要补一句**：改写与删除类取首字符，插入类取插入点（G-052、G-054、G-090 至 G-102 依赖这一约定）。
3. **一个输入可产生多条同位置记录**。G-090 有两条 R009 同在偏移 9，G-095 同一偏移上有 R010、R008、R009 三条。这符合「一次修改一条记录」，但对用户有噪声。若希望合并，需要改 BR-19，并同步修改 D09。
4. **G-077 只记 R008，不记 R011**。这是 D08 8.7 的字面结果：没有任何合法前缀的数字被替换为 null。若希望也记录被丢弃的残留，需要改规则。
5. **覆盖缺口**：本批没有覆盖 BR-18 的资源限制、孤立代理项（BR-12）、BR-21、选项矩阵（TC-O）和 R004 值位置的 BR-07a；下一批补齐。
