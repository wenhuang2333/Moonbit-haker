**三行上手示例**（接口草案，以实际发布版为准）

```moonbit
let result = @jsonmend.repair("{'a': 1,}")
println(result.text)          // 输出 {"a":1}
println(result.repairs.length())  // 修复记录条数
```

**流式示例**

```moonbit
let p = @jsonmend.PartialParser::new()
p.feed("{\"name\": \"Mo")
let s1 = p.snapshot()     // s1.value 为 {"name":"Mo"}，状态为 Partial
p.feed("on\"}")
let done = p.finish()     // done.value 为 {"name":"Mon"}
```

## 12.3 公共 API 摘要（README 与 mooncakes 页面使用）

| 符号 | 说明 |
| --- | --- |
| `repair` | 一次性修复，返回文本、修复记录、完整性 |
| `parse` | 一次性修复并返回 `Json` |

共约 14 个符号，符合 NFR-API-01。每个符号都必须有文档注释和至少一个可运行示例。

## 12.4 命令行帮助文本草案

```text
jsonmend [选项] [文件]

读取文件或标准输入，把修复后的 JSON 写到标准输出。

  --strict            严格模式：需要修复就报错（退出码 5）
  --check             只检查，不输出；需要修复时退出码 1
  --report            把修复记录写到标准错误
  --indent N          输出缩进空格数，默认紧凑输出
  --multi-root MODE   first、array 或 error，默认 first
  --skip-prose        跳过 JSON 之前的说明文字
  --quote-lookahead   启用引号歧义前瞻
  -h, --help          显示帮助
```

## 12.10 一页项目说明草稿（可直接用于申报，按需修改）

**项目名称**：JSONMend——流式 JSON 修复与部分解析库

**要解决的问题**：LLM 输出的结构化 JSON 经常被截断或带有瑕疵，流式场景下应用只能拿到前缀。TypeScript 与 Python 有成熟方案，MoonBit 生态中尚缺对应能力（以开工前的查重结论为准）。

**方案**：用增量式下推自动机加事件 sink 的单一引擎，同时提供一次性修复与流式部分解析；每次修改都有带位置的修复记录；支持严格模式与资源限制。

**与 MoonBit 的契合**：枚举与模式匹配适合写状态机；多后端与小体积适合在浏览器、服务端与命令行复用；与已有的 MCP 等 AI 工具链项目互补。

**可验证性**：属性测试（分块不变、快照单调、输出合法）、与 jsonrepair 的差分报告、多后端一致性。

**里程碑**：10-16 技术验证；10-21 一次性修复完成；10-25 流式完成；10-28 功能冻结；10-30 提交验收。

**风险与应对**：工期短，按优先级分层并预先约定削减顺序；选题重复，以差分报告与流式快照语义作差异化。

## 12.11 已知限制（对外披露）

- `snapshot()` 返回完整拷贝，代价与树大小成正比，高频调用时总体开销较大；FR-16 的事件接口可缓解。
- `Json` 数值遵循 core 的表示，大整数可能损失精度；修复后的文本保留数字原文。
- 引号前瞻默认关闭，开启后对缺逗号的字符串序列会偏向解释为内容。
- 修复记录有内部上限 10000 条。
- 解析器实例非线程安全，每个输入流应使用独立实例。
- 与 jsonrepair 存在有意差异，详见差分报告。
- 后端支持范围以发布时的测试结果为准。
